1. INTRODUCTION                                         *agentic-introduction*

agentic.nvim is a Claude-focused AI chat interface for Neovim, communicating
via the Agent Client Protocol (ACP). It provides a sidebar chat widget with
tool call rendering, diff previews, permission management, and session
persistence.

This is a fork of carlos-algms/agentic.nvim.

==============================================================================
2. REQUIREMENTS                                         *agentic-requirements*

- Neovim >= 0.12.0
- An ACP provider binary on PATH. `provider` takes the config key; the
  binary is what must be installed:

  Config key          Binary            Provider ~
  claude-agent-acp    claude-agent-acp  Claude (default)
  gemini-acp          gemini            Gemini (--experimental-acp)
  codex-acp           codex-acp         Codex
  opencode-acp        opencode          OpenCode (acp subcommand)
  cursor-acp          cursor-agent-acp  Cursor Agent
  auggie-acp          auggie            Auggie (--acp)
  mistral-vibe-acp    vibe-acp          Mistral Vibe

Install claude-agent-acp:
>
    pnpm add -g @agentclientprotocol/claude-agent-acp@0.66.0
<
Or download a binary from the releases page. That version is the one the
plugin is developed against, not a hard floor.

TREESITTER PARSERS                              *agentic-requirements-parsers*

The chat buffer enables the `markdown` treesitter parser and relies on its
language injection for fenced code blocks. `markdown` and `markdown_inline`
ship bundled with Neovim 0.12+.

Shell command blocks (execute tool calls, Bash tool output) are emitted
inside bash code fences. Syntax highlighting inside those fences needs
either the `bash` or the `zsh` parser; the plugin registers `zsh` as an
alias for `bash`, so either works. Without a shell parser, shell commands
render as plain text inside the fence.

Shell command auto-approval (|agentic-permissions-shell|) requires the
`zsh` parser specifically. Without it, no command auto-approves through
that path and every Bash command raises a permission prompt.

Parser installers are not shipped with Neovim core. Install via
nvim-treesitter (https://github.com/nvim-treesitter/nvim-treesitter) with
`:TSInstall bash` or `:TSInstall zsh`, or compile a parser manually with
`tree-sitter generate` and a C compiler.

3. SETUP                                                       *agentic-setup*

>lua
    require("agentic").setup({
        provider = "claude-agent-acp",
        -- ... any overrides (see |agentic-configuration|)
    })
<

All options with defaults are in `lua/agentic/config_default.lua`. Only
override what you need.

4. CONFIGURATION                                       *agentic-configuration*

------------------------------------------------------------------------------
4.1 PROVIDER                                         *agentic-config-provider*

                                                *agentic-config-provider-name*
`provider` string (default: `"claude-agent-acp"`)
    Name of the ACP provider to use. Must match a key in `acp_providers`;
    the keys are listed in |agentic-requirements|.

                                               *agentic-config-acp_providers*
`acp_providers` table
    Provider definitions. Each entry has:
      `name`      Display name
      `command`   Binary name or path
      `args`      List of CLI arguments (optional)
      `env`       Environment variables (optional)

                                                   *agentic-config-auth_type*
`auth_type` string (default: `"claudeai"`)
    Auth type for Claude CLI re-authentication. One of `"claudeai"`,
    `"console"`, `"sso"`.

------------------------------------------------------------------------------
4.2 WINDOWS                                           *agentic-config-windows*

                                                  *agentic-config-windows-tbl*
`windows` table
    Widget layout and sizing.

    `position`          `"right"` | `"left"` | `"bottom"` | `"tab"`
                        (default: `"right"`)
    `width`             string or number (default: `"50%"`)
    `height`            string or number (default: `"20%"`)
    `stack_width_ratio` number (default: 0.4)
    `max_wrap_width`    integer (default: 80)
    `min_wrap_width`    integer (default: 40)

    `"tab"` opens the widget in a dedicated tabpage with no file window and
    closes that tab on hide. The other three split the current tab.

    Chat prose is hard-wrapped to the chat window width, clamped between
    `min_wrap_width` and `max_wrap_width`. Setting either to 0 drops that
    bound. `max_wrap_width` also caps `min_wrap_width`. Wrapped lines run
    past the edge of a window narrower than `min_wrap_width`.

    Sub-tables for individual panels:
      `chat`          `{ win_opts = {} }`
      `input`         `{ height = 10, win_opts = {} }`
      `code`          `{ max_height = 15, win_opts = {} }`
      `files`         `{ max_height = 10, win_opts = {} }`
      `diagnostics`   `{ max_height = 10, win_opts = {} }`
      `activity`      `{ display = true, max_height = 10,`
                      ` hide_reverted = true, win_opts = {} }`
      `todos`         `{ display = true, max_height = 10, win_opts = {} }`
      `subagent`      `{ display = true, width = "40%",`
                      ` auto_close = false, win_opts = {} }`

    `activity.display` turns off both the panel and its count in the chat
    header. `activity.hide_reverted` drops rows whose change is no longer on
    disk; set it false to keep them. See |agentic-file-activity|.

    `subagent.display` routes subagent work into a split beside the chat.
    `subagent.width` takes a fraction (0-1), a percentage string, or a
    column count. `subagent.auto_close` closes the split once every
    subagent in the turn has finished. See |agentic-subagents|.

    `win_opts` is passed to |nvim_set_option_value()| for each window.

------------------------------------------------------------------------------
4.3 KEYMAPS                                           *agentic-config-keymaps*

                                                  *agentic-config-keymaps-tbl*
`keymaps` table
    Keybindings for the `widget`, `prompts`, `prompt`, `chat`,
    `diff_preview` and `permission` scopes. See |agentic-keymaps| for
    defaults. Each value can be:
      - A string (`"<CR>"`)
      - A list of strings
      - A list of `{ key, mode = ... }` entries

                                              *agentic-config-keymaps-prompts*
`keymaps.prompts` table
    Canned prompts: a key-to-text map applied to every widget buffer. The
    default binds `<localLeader>c` to "Continue". A value may be
    `{ prompt, mode, desc }` for mode and description control. Set a key to
    `vim.NIL` or `""` to disable an inherited binding; plain `nil` does not
    disable it. >lua
        require("agentic").setup {
            keymaps = { prompts = { ["<localLeader>y"] = "Go ahead." } },
        }
<
------------------------------------------------------------------------------
4.4 TOOL CALL DISPLAY                            *agentic-config-tool-display*

                                           *agentic-config-tool_call_display*
`tool_call_display` table
    Line thresholds for tool call output. A block over its threshold is
    folded closed; 0 disables that fold.

    `search_max_lines`         integer (default: 8)
        Lines before folding search output.
    `execute_max_lines`        integer (default: 25)
        Lines before folding execute output.
    `other_max_lines`          integer (default: 25)
        Lines before folding generic, MCP and meta tool-result bodies.
    `execute_formatter`        string | false (default: `"shfmt"`)
        External formatter for execute code blocks. Set to `false` to
        use the built-in operator-splitting fallback only.
    `diff_context_max_lines`   integer (default: 5000)
        Skip context-aware diff highlighting when the edited file exceeds
        this many lines. 0 disables the feature entirely.
    `create_max_lines`         integer (default: 50)
        Fold a created-file diff closed when it exceeds this many lines
        (0 = always open). Edits are never auto-collapsed.

4.5 DIFF PREVIEW                                 *agentic-config-diff-preview*

                                                *agentic-config-diff_preview*
`diff_preview` table
    `enabled`                    boolean (default: true)
    `layout`                     `"inline"` | `"split"` (default: `"split"`)
    `center_on_navigate_hunks`   boolean (default: true)

4.6 PERMISSIONS                                   *agentic-config-permissions*

                                *agentic-config-auto_approve_read_only_tools*
`auto_approve_read_only_tools` boolean (default: true)
    Auto-approve read-only tool calls (Read, Grep, Glob) without prompting,
    regardless of target path.

                                        *agentic-config-auto_approve_skills*
`auto_approve_skills` boolean (default: true)
    Auto-approve Skill tool calls without prompting.

                                              *agentic-config-permissions-tbl*
`permissions` table
    Bash command auto-approval. The rule layers, their precedence and the
    `structured` format are described in |agentic-permissions-shell|.

    `use_plugin_defaults`   boolean (default: true)
        Load the bundled patterns from `permissions.json`.
    `use_claude_settings`   boolean (default: true)
        Merge `Bash(...)` patterns from Claude's settings.json files.
    `auto_approve`          `"allow"` | `"read-only"` | nil
                            (default: `"allow"`)
        Selects which pattern kinds are auto-approved.
    `read_only`             string list (default: {})
        Additional read-only `Bash(...)` glob patterns.
    `safe_write`            string list (default: {})
        Additional safe-write glob patterns.
    `deny`                  string list (default: {})
        Deny `Bash(...)` glob patterns.
    `ask`                   string list (default: {})
        Ask patterns.
    `structured`            table (default: {})
        Cmd-keyed structured rules merged over the bundled defaults.
    `highlight_unapproved`  boolean (default: true)
        Highlight the non-known-safe parts of an execute prompt while shown.
    `trust_tmp`             boolean (default: true)
        Activate the `/trust tmp` scope at session start.
    `tmp_cleanup`           boolean (default: true)
        Under `/trust tmp`, auto-approve a plain `rm` of scratch files
        created earlier in the same Bash command. `rm -f` / `rm --force`
        is always rejected.

                                     *agentic-config-auto_approve_trust_scope*
`auto_approve_trust_scope` boolean (default: true)
    Gate the per-session `/trust` scope check. See
    |agentic-permissions-trust|.

                                            *agentic-config-permission_float*
`permission_float` table
    Floating window that renders permission prompts, anchored to a corner
    of the chat window.

    `anchor`       `"NE"` | `"NW"` | `"SE"` | `"SW"` (default: `"SE"`)
    `width`        integer (default: 30)
        Content width in columns; the border is drawn around it.
    `row_offset`   integer (default: 1)
        Inset from the anchored corner. Positive is down for `"N*"`, up
        for `"S*"`.
    `col_offset`   integer (default: -1)
        Inset from the anchored corner. Positive is right for `"*W"`, left
        for `"*E"`.
    `border`       string or string list (default: `"rounded"`)
        |nvim_open_win()| border style.
    `winblend`     integer 0..100 (default: 0)

                                            *agentic-config-permission_icons*
`permission_icons` table
    Icon per permission option kind: `plan_implement`, `allow_once`,
    `allow_always`, `reject_once`, `__reject_all__`, `reject_always`.

------------------------------------------------------------------------------
4.7 SESSION RESTORE                           *agentic-config-session-restore*

                                             *agentic-config-session_restore*
`session_restore` table
    `storage_path`      string | nil
                        (default: `~/.cache/nvim/agentic/sessions/`)
    `picker`            `"quickfix"` | `"fzf-lua"` | `"select"`
                        (default: `"quickfix"`)
        Session picker backend. `"quickfix"` offers delete, undo and a
        scope toggle; `"fzf-lua"` adds a preview and falls back to
        quickfix when not installed; `"select"` delegates to
        |vim.ui.select()| and offers neither scope toggle nor delete.
    `confirm_delete`    boolean (default: true)
        Prompt before `/delete`.
    `cd_on_load`        boolean (default: true)
        Change nvim's working directory to the session's recorded cwd on
        load. Applies to the picker, `:AgenticResume` and
        |agentic.load_acp_session()|.

------------------------------------------------------------------------------
4.8 HOOKS                                               *agentic-config-hooks*

                                                   *agentic-config-hooks-tbl*
`hooks` table
    Callback functions for lifecycle events:
      `on_prompt_submit`       Fires after submitting a prompt. Once per
                               dispatched block, so a submit that splits at a
                               command line fires it more than once.
      `on_response_complete`   Fires when response finishes. Once per
                               submitted prompt, so turns resent by
                               |agentic-config-auto_retry_on_transient_error|
                               report only the final outcome.
      `on_permission_request`  Fires on tool permission prompt.

    Each receives a data table with `session_id`, `tab_page_id`, and
    event-specific fields. See type annotations in `config_default.lua`.

------------------------------------------------------------------------------
4.9 SETTINGS                                         *agentic-config-settings*

                                                 *agentic-config-settings-tbl*
`settings` table
    `move_cursor_to_chat_on_submit`  boolean (default: false)
        Move focus to the chat window after submitting a prompt.
    `send_register`                  string | nil (default: nil)
        Register to copy the sent text into before a partial send deletes
        it from the input buffer. Nil writes no register.
    `write_submit`                   boolean (default: true)
        Register the `:w` / `:wq` / `:x` submit handling in the input
        buffer. When false the input buffer stays a plain `nofile` buffer.

4.10 MISCELLANEOUS                                       *agentic-config-misc*

                                *agentic-config-auto_continue_on_usage_limit*
`auto_continue_on_usage_limit` boolean (default: true)
    When the provider reports a usage limit with a reset time, schedule
    a timer to send "continue" automatically.

                               *agentic-config-auto_retry_on_transient_error*
`auto_retry_on_transient_error` boolean (default: true)
    When a turn ends in a transient server error (connection closed
    mid-response, API unreachable, overloaded), send "continue"
    immediately as a new turn, up to 3 times. The retried turns write
    nothing to the chat: no prompt heading, no error block, no bell or
    unread badge. Once the budget runs out the error is written as
    usual, followed by the number of attempts made.

    Tools already run in a retried turn may run again, as they would if
    you sent "continue" by hand.

                                                      *agentic-config-winbar*
`winbar` boolean (default: true)
    Set 'winbar' on widget windows to the full header text.

                                              *agentic-config-budget_display*
`budget_display` boolean (default: true)
    Show the claude.ai subscription rate-limit budget in the chat header:
    the binding window ("5h" five-hour or "wk" weekly), the time until it
    resets, and the utilisation percentage when available. Only shown
    under claude.ai subscription auth.

                                                     *agentic-config-headers*
`headers` table
    Customise window headers per panel. Each entry can be a table with a
    `title` field or a function receiving header parts.

                                               *agentic-config-notifications*
`notifications` table

        Ring the vim bell when the agent needs attention. See

                                                 *agentic-config-file_picker*
`file_picker` table
    `enabled`       boolean (default: true)
    `max_files`     integer (default: 20000)

                                                 *agentic-config-image_paste*
`image_paste` table

                                                 *agentic-config-auto_scroll*
`auto_scroll` table

    `pause_on_prose`    boolean (default: true)

    `bottom_padding`    integer (default: 1)
        Rows kept below the last buffer line.

                                                 *agentic-config-status_icons*
`status_icons` table
    Tool call state icons: `pending`, `in_progress`, `completed`, `failed`,
    `cancelled`.

                                             *agentic-config-diagnostic_icons*
`diagnostic_icons` table
    Context panel diagnostic icons: `error`, `warn`, `info`, `hint`.

                                                       *agentic-config-debug*

5. LUA API                                                       *agentic-api*

All functions are on `require("agentic")`.

                                                             *agentic.setup()*
agentic.setup({opts})
    Initialise the plugin. Call once from your config. See
    |agentic-configuration| for available options.

                                                              *agentic.open()*
agentic.open({opts})
    Open the chat sidebar. Optional `opts` table.

                                                             *agentic.close()*
agentic.close({tab_page_id})
    Close the chat sidebar. Optional tab page ID.

                                                            *agentic.toggle()*
agentic.toggle({opts})
    Toggle the chat sidebar open/closed.

                                                        *agentic.toggle_tab()*
agentic.toggle_tab({opts})
    Toggle the chat in a dedicated tab. Optional `opts` table.

                                                     *agentic.rotate_layout()*
agentic.rotate_layout({layouts})
    Cycle the sidebar through layout positions. Optional list of positions.

                                                       *agentic.send_prompt()*
agentic.send_prompt({text})
    Send {text} as a prompt to the active session. The prompt is held and
    sent later if the session cannot take it yet; a second call before the
    first is sent replaces it.

                                                     *agentic.add_selection()*
agentic.add_selection({opts})
    Add the current visual selection to the context panel.

                                                          *agentic.add_file()*
agentic.add_file({opts})
    Add the current file to the context panel.

                                  *agentic.add_selection_or_file_to_context()*
agentic.add_selection_or_file_to_context({opts})
    Add visual selection if active, otherwise the current file.

                                      *agentic.add_current_line_diagnostics()*
agentic.add_current_line_diagnostics({opts})
    Add diagnostics from the cursor line to context.

                                           *agentic.add_buffer_diagnostics()*
agentic.add_buffer_diagnostics({opts})
    Add all buffer diagnostics to context.

                                                       *agentic.new_session()*
agentic.new_session({opts})
    Start a new chat session.

                                         *agentic.new_session_with_provider()*
agentic.new_session_with_provider({opts})
    Start a new session with a provider picker.

                                                   *agentic.switch_provider()*
agentic.switch_provider({opts})
    Switch to a different ACP provider.

                                                   *agentic.stop_generation()*
agentic.stop_generation()
    Stop the current response generation.

                                              *agentic.toggle_file_activity()*
agentic.toggle_file_activity()
    Show or hide the panel listing the files this session's agent has
    changed. See |agentic-file-activity|.

                                                   *agentic.restart_session()*
agentic.restart_session()
    Restart the current session (new process).

                                                   *agentic.restore_session()*
agentic.restore_session()
    Open the session restore picker. Most providers resume with full
    native memory of the session. Some cannot, in which case the saved
    transcript is replayed as context on the next prompt: the
    conversation continues, but the provider has no native memory of
    the prior turns.

                                                  *agentic.load_acp_session()*
agentic.load_acp_session({session_id}, {cwd}, {model})
    Load a specific ACP session by UUID. Optional {cwd} for the working
    directory and {model} for the model id saved with the session. On
    failure, falls back to the local-history replay described under
    |agentic.restore_session()|.

                                                   *agentic.resolve_session()*
agentic.resolve_session({query}, {callback})
    Resolve {query} — a `session_id` prefix or an exact title,
    case-insensitive — against the session cache. {callback} receives
    `session_id`, `cwd` and `model`, or nil when zero or several sessions
    match.

                                                      *agentic.resume_query()*
agentic.resume_query({query})
    Resolve {query} as |agentic.resolve_session()| does and open the
    session in a new tab. No match emits a notification and changes
    nothing.

                                                 *agentic.send_operatorfunc()*
agentic.send_operatorfunc({type})
    'operatorfunc' callback for sending a motion/selection as a prompt.

6. KEYMAPS                                                   *agentic-keymaps*

Buffer-local keymaps set automatically in agentic buffers. All are
configurable via `keymaps` in |agentic-config-keymaps|.

------------------------------------------------------------------------------
6.1 WIDGET KEYMAPS                                    *agentic-keymaps-widget*

Applied to all buffers in the widget (chat, prompt, panels).

    Key              Mode    Description ~
    `<localLeader>m`   n/v     Switch agent mode
    `<C-c>`            n/i     Stop generation
    `<localLeader>c`   n       Send "Continue" (canned prompt)
    `<localLeader>R`   n       Restore session
    `<localLeader>s`   n       Switch provider
    `<localLeader>M`   n       Switch model
    `<localLeader>q`   n       Close widget
    `<localLeader>!`   n       Restart session
    `<localLeader>f`   n       Toggle changed-files panel
    `<localLeader>a`   n       Toggle auto-scroll
    `<localLeader>G`   n       Scroll chat and subagents to bottom, keep focus

Canned prompts live in `keymaps.prompts` (|agentic-config-keymaps-prompts|).

------------------------------------------------------------------------------
6.2 PROMPT KEYMAPS                                    *agentic-keymaps-prompt*

    Key              Mode    Description ~
    `<CR><CR>`         n       Send N lines (count1), delete them
    `<CR>{motion}`     n       Send the motion range, delete
    `<CR>`             x       Send the visual selection, delete
    `<S-CR><S-CR>`     n       Queue N lines (count1) for later dispatch
    `<S-CR>{motion}`   n       Queue the motion's line(s) for dispatch
    `<S-CR>`           x       Queue the selected line(s) for dispatch
    `<S-C-c>`          n       Drop every queued region (text stays as draft)
    `:w`               c       Submit whole buffer
    `:wq` / `:x`       c       Submit, then close the input window
    `:wq!` / `:x!`     c       Submit, then close the widget
    `:q`               c       Close the input window if empty, else warn
    `<localLeader>p`   n       Paste image
    `<C-v>`            i       Paste image

`<S-CR>` and `<S-C-c>` require the kitty keyboard protocol (kitty terminal
with nvim 0.12), which is what distinguishes them from `<CR>` and `<C-c>`.

The `:w` family is registered only while `settings.write_submit` is on
(|agentic-config-settings|). What the queue bindings dispatch, and when, is
in |agentic-queue|.

------------------------------------------------------------------------------
6.3 CHAT KEYMAPS                                        *agentic-keymaps-chat*

    Key    Mode    Description ~
    `[[`     n       Previous prompt or command notice
    `]]`     n       Next prompt or command notice
    `gf`     n       Open the file under the cursor at the diff's line
    `:q`     c       Warns and closes nothing (`:q!` closes the chat window)

Tool output over its line threshold (|agentic-config-tool-display|) is
folded; |zo|, |zc| and |za| toggle a fold as usual.

An insert key (`i`, `a`, `o`, `c`, `x`, ...) in the chat or a panel moves the
cursor to the input window and starts insert there, reopening the input window
first if it was closed.

7. COMMANDS                                                 *agentic-commands*

------------------------------------------------------------------------------
7.1 LOCAL COMMANDS                                    *agentic-commands-local*

Slash commands the plugin answers itself, without forwarding them to the
provider. They are available whether or not the provider advertises them,
and appear in slash-command completion.

    `/new [name]`      Start a fresh session, named if a name is given.

    `/trust [scope]`   Set the edit trust scope. See
                       |agentic-permissions-trust|.

A command line dispatches as its own prompt; see |agentic-queue|.

------------------------------------------------------------------------------
7.2 FORWARDED COMMANDS                            *agentic-commands-forwarded*

Slash commands the provider advertises over ACP and the plugin passes

    `/init`             Generate a project `CLAUDE.md`.
    `/review`           Pull-request review.
    `/security-review`  Security review of pending changes.
    `/compact`          Summarise and compact conversation history.
    `/extra-usage`      Configure extra usage when limits hit.
    `/insights`         Session analysis report.
    `/team-onboarding`  Teammate-ramp guide.
    `/heapdump`         Dump JS heap for bridge debugging.

The set is provider-specific and changes with the bridge version.

------------------------------------------------------------------------------
7.3 COMMAND NOTICES                                          *agentic-notices*

`/trust`, `/rename`, `/context`, a model or provider switch and a resumed
session report back in the chat as a notice heading rather than as agent
prose.

`[[` and `]]` stop on notices as well as prompts
(|agentic-keymaps-chat|). Notices are not saved with the session and not
replayed on restore.

7.4 :AGENTICRESUME                                   *agentic-commands-resume*

8. PERMISSIONS                                           *agentic-permissions*

------------------------------------------------------------------------------
8.1 THE PERMISSION PROMPT                         *agentic-permissions-prompt*

A tool call the agent is not cleared to make raises a prompt in a float
anchored to the chat window (|agentic-config-permission_float|). The options
come from the provider; the plugin inserts "Reject all" ahead of the
provider's "Reject always", or appends it when there is none. The number
keys pick by position (|agentic-keymaps-permission|).

    Option          Effect ~
    Allow once      Approve this call.
    Allow always    Approve, and approve the same operation for the rest of
                    the session without prompting.
    Reject once     Reject this call.
    Reject all      Reject this call and cancel every call still queued for
                    the turn. No rule is stored.
    Reject always   Reject, and reject the same operation for the rest of
                    the session without prompting.

The always-decisions are held in a per-session cache keyed on the
operation's identity — file path, command, URL, query — so a decision on one
call does not carry to a different call of the same tool. The cache is
dropped with the session.

While an execute prompt is shown, the parts of the command that are not
known-safe are highlighted (`permissions.highlight_unapproved`,
|AgenticUnapprovedCommand|).

------------------------------------------------------------------------------
8.2 AUTO-APPROVAL                                   *agentic-permissions-auto*

A tool call runs without a prompt when any of these holds:

- It is a read-only tool (Read, Grep, Glob) and
  `auto_approve_read_only_tools` is on, regardless of target path.
- It is a Skill tool call and `auto_approve_skills` is on. Loading a skill
  injects a SKILL.md into the context.
- It is a shell command every leaf of which matches an allow rule
  (|agentic-permissions-shell|).
- It matches a cached "Allow always" decision
  (|agentic-permissions-prompt|).
- It writes a file covered by the active trust scope
  (|agentic-permissions-trust|).

A shell command matching a `deny` rule is rejected outright, with no prompt
and without running.

------------------------------------------------------------------------------
8.3 TRUST SCOPES                                   *agentic-permissions-trust*

`/trust` sets a per-session scope in which file-scoped tool calls — edit,
write, create, delete, move — auto-approve. Bare `/trust` opens a picker.

    `/trust repo`     Git-tracked files anywhere in the repository.
    `/trust here`     Git-tracked files under the current directory.
    `/trust tmp`      Scratch files under `/tmp` and `$TMPDIR`.
    `/trust off`      Clear the scope.
    `/trust {path}`   A path or glob. Relative paths anchor at the cwd.

`repo` and `here` need a git repository at the cwd; without one the command
reports an error and leaves the scope untouched. A scope covering a home or
system directory writes a warning notice.

Inside the scope a file auto-approves only when the change is recoverable:
a pure addition, a tracked file with no uncommitted change, or a recorded
agent-owned line range whose content still matches the file on disk.
Symlinks are resolved to their target, and the file is re-checked against
its recorded size and mtime immediately before the write.

`/trust tmp` is active from session start while `permissions.trust_tmp` is
on. `permissions.tmp_cleanup` extends it to a plain `rm` of a scratch file
created earlier in the same Bash command; `rm -f` and `rm --force` are
always rejected.

The whole mechanism is gated by `auto_approve_trust_scope`.

------------------------------------------------------------------------------
8.4 SHELL COMMANDS                                 *agentic-permissions-shell*

Every Bash command is parsed with the `zsh` treesitter grammar
(|agentic-requirements-parsers|) and its leaf commands are matched one by
one, so `cd /path && git status` matches `Bash(git *)` on its `git` leaf.

The walk rejects by default: a missing parser, a parse error, command or
process substitution (`$(...)`, backticks, `<(...)`), control flow (loops,
conditionals, subshells, functions), a file-writing redirect (anything but
`/dev/null` and fd duplication such as `2>&1`), a dynamic command name, or
a code-taking builtin (`eval`, `source`, `.`) all fall through to a prompt.

Each remaining leaf is stripped of a `stdbuf` wrapper and a system
binary-dir prefix, then checked against two layers:

- Glob rules: `Bash(...)` patterns from `~/.claude/settings.json` and
  `.claude/settings.json`, plus the `read_only`, `safe_write`, `deny` and
  `ask` lists in `permissions`.
- Structured rules: the bundled `permissions.json` plus
  `permissions.structured`. These match on tokenised flag identifiers, so
  option clustering (`sort -uo out`), GNU abbreviation (`sort --out=x`)
  and glued arguments (`sort -oFILE`) are matched.

A leaf auto-approves when a layer allows it and no layer denies or asks.
`deny` rejects the command immediately, with no prompt and no execution;
`ask` withholds approval so the command prompts. Which allow rules count
follows `permissions.auto_approve`: `"allow"` admits read-only and
safe-write rules, `"read-only"` admits read-only only, nil admits none.

Structured rules are a cmd-keyed table. Each command maps to up to four
gate-kind arrays — `read_only`, `safe_write`, `ask`, `deny` — and each gate
constrains `options` (literal flag identifiers) and/or `positionals`
(literal or glob, matched in order). `read_only` auto-approves at
`"read-only"` and `"allow"`, `safe_write` only at `"allow"`, `ask`
withholds approval, `deny` rejects. `permissions.structured` is deep-merged
over the bundled defaults: a cmd key replaces that command's bundled
kind-arrays wholesale, and `vim.NIL` disables the bundled entry. >lua
    require("agentic").setup({
        permissions = {
            structured = {
                -- Auto-approve `tee` when writing (safe_write kind).
                tee = { safe_write = { {} } },
                -- Disable the bundled `rm` prompt.
                rm = vim.NIL,
                -- Silence pacman's destructive-flag ask.
                pacman = { ask = {} },
            },
        },
    })
<

9. CHAT BEHAVIOUR                                               *agentic-chat*

------------------------------------------------------------------------------
9.1 AUTO-SCROLL AND ATTENTION                            *agentic-auto-scroll*

While the agent streams, the chat follows the trailing edge of the buffer.
Scrolling the chat window away from the bottom stops the following until the
view reaches the bottom again. `<localLeader>a` toggles auto-scroll off and
on; `<localLeader>G` returns the chat and the subagent split to the bottom
without moving focus.

With `pause_on_prose` the start of each prose run is pinned to the top of
the viewport, released by the next write to chat. In practice only the final
prose run's pin persists, leaving the view on the agent's summary.
`auto_scroll.bottom_padding` rows are kept below the last buffer line.

When a turn completes, and when a permission prompt needs an answer, the
plugin signals two ways:

- The vim bell rings if the chat window is not the current window
  (`notifications.bell`, off by default). Focus in another window of the
  widget, the input window included, still rings it.
- The chat buffer name carries an unread badge if the chat is scrolled away
  from the bottom. The badge clears when the chat reaches the bottom again.
  A permission prompt sets no badge; its float is visible regardless of
  scroll position.

Auto-approved requests do neither.

------------------------------------------------------------------------------
9.2 MESSAGE QUEUE                                              *agentic-queue*

Submitted text splits at command lines: a line of the form `/word`, with or
without arguments, is a prompt of its own, and each run of other lines is one
prompt. They dispatch in buffer order, one per turn — `/compact` above
`Continue` compacts, then sends `Continue` when that finishes. Text with no
command line in it is one prompt. An argument belongs on its command's own
line; the line below it is the next prompt. A `/`-leading line indented by
one space is ordinary text.

The queue bindings (|agentic-keymaps-prompt|) tag the covered line(s) as a
queued region (`AgenticQueuedRegion`, |agentic-highlights|) instead of
sending now — always, whether or not a turn is running. Queueing is
line-granular: a charwise motion queues its whole line(s). A submit the
session cannot take yet is tagged the same way, as is every block of one that
has not dispatched.

The queue dispatches one block in buffer order at each turn that ends
normally, and one when a session becomes ready. A turn stopped with `<C-c>`,
or ended early by the agent, leaves the rest tagged. Editing a region — any
change to it, or entering insert mode with the cursor inside it — drops it
back to ordinary draft. `:w` / `:wq` / `:x` submit the whole buffer through a
usage limit; with no session yet, or a session still loading, they queue like
any other submit.

`/new`, `/clear` and `/delete` ask for confirmation when they dispatch from
the queue rather than as a submit's first block. Declining leaves every
queued block as draft. `/delete` also drops the rest of the queue.

A partial send deletes the sent text from the input buffer;
`settings.send_register` copies it to a register first.

------------------------------------------------------------------------------
9.3 FILE ACTIVITY                                      *agentic-file-activity*

A toggled panel listing the files the agent has changed over the session,
one row per file however many times it was touched. Subagent (Task) edits
appear alongside the main agent's, unmarked.

Toggle with `<localLeader>f`. The chat header carries the number of changed
files.

    Row      Meaning ~
    `+ path`   File created
    `~ path`   File changed
    `- path`   File deleted

A `●` in the panel's sign column marks a row changed since the panel was last
open. The marks clear when the panel is closed, and survive a resume.

Rows are ordered by change class (changes above plain reads), then by
location (project files, elsewhere, then scratch), then alphabetically.
Inside the panel:

    Key   Description ~
    `<CR>`  Open the file at its first recorded change
    `Q`     Send every row to the |quickfix| list

Opening the panel drops rows whose change is no longer on disk: a created
file that no longer exists, and a tracked file that no longer differs from
HEAD — so committing the agent's work drops its rows. Rows for untracked
files that still exist, and every row outside a git repository, stay.
`windows.activity.hide_reverted = false` keeps them all.

The list survives |agentic.restore_session()| and a provider switch. `/new`
and `/clear` start a new conversation, and empty it.

Only the file-editing tools are tracked. Files a shell command changes are
not listed.

------------------------------------------------------------------------------
9.4 SUBAGENTS                                              *agentic-subagents*

Subagent (Task) work renders in a split beside the chat rather than inline,
configured under `windows.subagent` (|agentic-config-windows|).

A subagent's prose and thinking appear there alongside its tool calls with
claude-agent-acp 0.66.0 and later. Earlier bridges send only the tool calls.

`<localLeader>G` returns the subagent split to the bottom along with the
chat.

14. COMPARISON WITH CLAUDE TUI                                *agentic-vs-tui*

Against the native `claude` CLI as of Claude Code v2.1.x.

------------------------------------------------------------------------------
14.1 BEHAVIOUR DIFFERENCES                              *agentic-vs-tui-diffs*

Same feature, different behaviour:

- Text wrapping and yanking: the TUI hard-wraps chat text to the terminal
  width, which can corrupt pasted text on copy. This plugin uses neovim's
  native soft-wrap, so yanks preserve the original text.
- Scrolling: the TUI auto-scrolls aggressively during streaming. See
  |agentic-auto-scroll| for this plugin's pin + pause-on-user-scroll
  behaviour.
- Permission rules: the TUI scopes read-only tools to the working directory
  and `additionalDirectories`; this plugin approves them regardless of path
  (|agentic-permissions-auto|).
- Sessions: the TUI runs one session per process; this plugin runs one per
  tabpage, with its own chat, panels and permission prompts.

------------------------------------------------------------------------------
14.2 NOT AVAILABLE                                    *agentic-vs-tui-missing*

TUI features this plugin does not currently provide:

Workflow commands ~
- `/diff` interactive diff viewer across uncommitted changes and per-turn
  diffs. The plugin only renders per-edit diffs at the tool-call level.
- `/rewind` conversation checkpoints.
- `/branch` forks the current conversation.
- `/teleport` pulls in a web session.
- Background jobs.

Interactive management UIs ~
- `/permissions` interactive rule editor. ACP has no protocol surface
  for reading or writing persistent permission rules. Edit
  `~/.claude/settings.json` (or `.claude/settings.json`) directly.
- `/agents` subagent management (list, create, edit, delete).
- `/skills` skill management.
- `/mcp` MCP-server management.
- `/config` interactive config editor.
- `/doctor` installation health check.
- `/login`, `/logout` authentication flow.
- `/status` session status display.
- `/cost`, `/stats`, `/usage` usage and cost readouts.
- `/bug` bug reporter.
- `/memory`, `/hooks`, `/bashes`, `/pr-comments`, `/vim`, `/ide`.

All of the above are either filtered out by the bridge
(`/cost`, `/login`, `/logout`) or simply not advertised by it.

Runtime controls ~
- `/effort` dynamic thought-level control. The ACP schema reserves
  `thought_level` as a config-option category but claude-agent-acp does
  not emit it.

Input ~
- PDF attachments. The plugin supports image drag-and-drop (see
  |agentic-config-image_paste|) but not PDF uploads.
