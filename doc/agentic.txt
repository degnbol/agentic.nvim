1. INTRODUCTION                                         *agentic-introduction*

agentic.nvim is a Claude-focused AI chat interface for Neovim, communicating
via the Agent Client Protocol (ACP). It provides a chat buffer with context
panels, tool call rendering, permission management, and session persistence.

This is a fork of carlos-algms/agentic.nvim.

==============================================================================
2. REQUIREMENTS                                         *agentic-requirements*

- Neovim >= 0.12.0
- An ACP provider binary on PATH. `provider` takes the config key; the
  binary is what must be installed:

  Config key          Binary            Provider ~
  claude-agent-acp    claude-agent-acp  Claude (default)
  gemini-acp          gemini            Gemini (--experimental-acp)
  codex-acp           codex-acp         Codex
  opencode-acp        opencode          OpenCode (acp subcommand)
  cursor-acp          cursor-agent-acp  Cursor Agent
  auggie-acp          auggie            Auggie (--acp)
  mistral-vibe-acp    vibe-acp          Mistral Vibe

Install claude-agent-acp:
>
    pnpm add -g @agentclientprotocol/claude-agent-acp@0.97.0
<
Or download a binary from the releases page. Developed against
claude-agent-acp 0.97.0.

TREESITTER PARSERS                              *agentic-requirements-parsers*

The chat buffer enables the `markdown` treesitter parser and relies on its
language injection for fenced code blocks. `markdown` and `markdown_inline`
ship bundled with Neovim 0.12+.

Highlighting in shell command blocks needs the `bash` or `zsh` parser.

Shell command auto-approval (|agentic-permissions-shell|) requires the
`zsh` parser specifically. Without it, no command auto-approves through
that path and every Bash command raises a permission prompt.

Install via nvim-treesitter
(https://github.com/nvim-treesitter/nvim-treesitter) with `:TSInstall bash`
or `:TSInstall zsh`, or compile a parser manually with
`tree-sitter generate` and a C compiler.

==============================================================================
3. SETUP                                                       *agentic-setup*

The plugin works without a setup call. To change options, call `setup()`
before the first session:
>lua
    require("agentic").setup({
        provider = "claude-agent-acp",
        -- ... any overrides (see |agentic-configuration|)
    })
<

All options with defaults are in `lua/agentic/config_default.lua`.

4. CONFIGURATION                                       *agentic-configuration*

------------------------------------------------------------------------------
4.1 PROVIDER                                         *agentic-config-provider*

                                                *agentic-config-provider-name*
`provider` string (default: `"claude-agent-acp"`)
    Name of the ACP provider to use. Must match a key in `acp_providers`;
    the keys are listed in |agentic-requirements|.

                                               *agentic-config-acp_providers*
`acp_providers` table
    Provider definitions. Each entry has:
      `name`      Display name
      `command`   Binary name or path
      `args`      List of CLI arguments (optional)
      `env`       Environment variables (optional)
      `auth_method`
                  Id of the preferred login method (optional). `/login`
                  runs it without asking when the provider advertises it.
                  An `agent`-type method also runs each time the provider
                  starts. `claude-agent-acp` advertises `claude-ai-login`
                  (the default, a Claude subscription) and `console-login`.

    The `claude-agent-acp` entry also has the fields below.

                                                  *agentic-config-todo_tools*
`todo_tools` boolean (default: true)
    Offer the agent the Claude Code todo/task tools (TaskCreate, TaskUpdate,
    TaskList, TaskGet, TodoWrite). These tools fill the todos split.

                                               *agentic-config-allowed_tools*
`allowed_tools` list
    (default: `{ "Grep(//dev/null/**)", "Glob(//dev/null/**)" }`)
    Claude Code permission rules, passed as `--allowedTools`. Naming `Grep`
    or `Glob`, with or without a scope, gives the agent both tools. Without
    either, the agent has neither. Naming `TodoWrite` or a `Task*` tool gives
    the agent the todo tools, whatever |agentic-config-todo_tools| is set to.

    A tool call that a rule here matches bypasses the permission prompt,
    |agentic-config-auto_approve_kinds| and |agentic-permissions-grant|. The
    default scope matches no path, so the default rules approve nothing.

                                                   *agentic-config-subagents*
`subagents` table (default: `{ force_background = false }`)
    `force_background` runs every subagent (Task) in the background, whatever
    the model passes for `run_in_background`. Background subagents have no
    Agent or LSP tool. An `Agent` PreToolUse hook of your own that rewrites
    the tool input can undo this.

                                              *agentic-config-budget_display*
`budget_display` boolean (default: true)
    Show the claude.ai subscription rate-limit budget in the chat header:
    the binding window ("5h" five-hour or "wk" weekly), the time until it
    resets, and the utilisation percentage when available. Only shown
    under claude.ai subscription auth.

                                *agentic-config-auto_continue_on_usage_limit*
`auto_continue_on_usage_limit` boolean (default: true)
    When the provider reports a usage limit with a reset time, schedule
    a timer to send "continue" automatically.

------------------------------------------------------------------------------
4.2 WINDOWS                                           *agentic-config-windows*

                                                  *agentic-config-windows-tbl*
`windows` table
    Panels and wrapping.

    `stack`             list (default: `{ "todos", "code", "files",`
                        `"diagnostics", "activity", "input" }`)
    `max_wrap_width`    integer (default: 80)
    `min_wrap_width`    integer (default: 40)

    `stack` is the top-to-bottom order of the panels below the chat's
    window (|agentic-buffers|). It must list each of the six exactly once.

    Chat prose is hard-wrapped to the chat window width, clamped between
    `min_wrap_width` and `max_wrap_width`. Setting either to 0 drops that
    bound. `max_wrap_width` also caps `min_wrap_width`. Wrapped lines run
    past the edge of a window narrower than `min_wrap_width`.

    Sub-tables for individual panels:
      `chat`          `{ win_opts = {} }`
      `input`         `{ height = 10, win_opts = {} }`
      `code`          `{ max_height = 15, win_opts = {} }`
      `files`         `{ max_height = 10, win_opts = {} }`
      `diagnostics`   `{ max_height = 10, win_opts = {} }`
      `activity`      `{ display = true, max_height = 10,`
                      ` hide_reverted = true, win_opts = {} }`
      `todos`         `{ display = true, max_height = 10, win_opts = {} }`
      `subagent`      `{ win_opts = {} }`

    `activity.display` turns off both the panel and its count in the chat
    header. `activity.hide_reverted`: see |agentic-file-activity|.

    `win_opts` is passed to |nvim_set_option_value()| for each window.

------------------------------------------------------------------------------
4.3 KEYMAPS                                           *agentic-config-keymaps*

                                                  *agentic-config-keymaps-tbl*
`keymaps` table
    Keybindings for the `widget`, `prompts`, `prompt`, `chat` and
    `permission` scopes. See |agentic-keymaps| for defaults.
    Each value can be:
      - A string (`"<CR>"`)
      - A list of strings
      - A list of `{ key, mode = ... }` entries

                                              *agentic-config-keymaps-prompts*
`keymaps.prompts` table
    Canned prompts: a key-to-text map applied to every widget buffer. The
    key puts the text at the end of the input, with a blank line before it
    when the input has text, and moves the cursor to it in normal mode. Send
    or queue it with the keys in |agentic-keymaps-prompt|. The default binds
    `<localLeader>c` to "Continue". A value may be
    `{ prompt, mode, desc }` for mode and description control. Set a key to
    `vim.NIL` or `""` to disable an inherited binding; plain `nil` does not
    disable it. >lua
        require("agentic").setup {
            keymaps = { prompts = { ["<localLeader>y"] = "Go ahead." } },
        }
<
------------------------------------------------------------------------------
4.4 TOOL CALL DISPLAY                            *agentic-config-tool-display*

                                           *agentic-config-tool_call_display*
`tool_call_display` table
    Line thresholds for tool call output. A block over its threshold is
    folded closed; 0 disables that fold.

    `search_max_lines`         integer (default: 8)
        Lines before folding search output.
    `execute_max_lines`        integer (default: 25)
        Lines before folding execute output.
    `other_max_lines`          integer (default: 25)
        Lines before folding generic, MCP and meta tool-result bodies.
    `execute_formatter`        string | false (default: `"shfmt"`)
        External formatter for execute code blocks. Set to `false` to
        use the built-in operator-splitting fallback only.
    `diff_context_max_lines`   integer (default: 5000)
        Skip context-aware diff highlighting when the edited file exceeds
        this many lines. 0 disables the feature entirely.
    `create_max_lines`         integer (default: 50)
        Fold a created-file diff closed when it exceeds this many lines
        (0 = always open). Edits are never auto-collapsed.

------------------------------------------------------------------------------
4.5 PERMISSIONS                                   *agentic-config-permissions*

                                              *agentic-config-permissions-tbl*
`permissions` table
    Tool call auto-approval. The shell rule layers, their precedence and the
    `structured` format are described in |agentic-permissions-shell|.

    `use_plugin_defaults`   boolean (default: true)
        Load the bundled rules from `permissions.json`.
    `use_claude_settings`   boolean (default: true)
        Use the `Bash(...)` rules in Claude's settings.json files.
                                       *agentic-config-auto_approve_kinds*
    `auto_approve_kinds`    string list
                            (default: { "read", "search", "skill" })
        Tool kinds approved without a prompt, whatever the target path. A
        kind is the one shown in a tool call's heading: a protocol kind or
        one the adapter adds, such as `skill` or `websearch`. Compared
        case-insensitively. A shell `deny` rule or a "Reject always"
        decision still rejects a call of a listed kind.
    `auto_approve_tier`     "safe_write" | "read_only" | nil
                            (default: "safe_write")
        Selects which allow rules auto-approve an execute call.
    `structured`            table (default: {})
        Cmd-keyed rules merged over the bundled rules.
    `highlight_unapproved`  boolean (default: true)
        Enable |AgenticUnapprovedCommand|.
    `default_grant`         string list
                            (default: { "/tmp", "$TMPDIR", ".", "root" })
        Paths or globs granted at session start. `{}` starts a session
        without grants. See |agentic-permissions-grant|.
    `tmp_cleanup`           boolean (default: true)
        Auto-approve `rm` of a tmp file redirected to earlier in the same
        command. See |agentic-permissions-grant|.

                                            *agentic-config-permission_float*
`permission_float` table
    Floating window that renders permission prompts, anchored to a corner
    of the window showing the tool call.

    `anchor`       `"NE"` | `"NW"` | `"SE"` | `"SW"` (default: `"SE"`)
    `width`        integer (default: 30)
        Content width in columns; the border is drawn around it.
    `row_offset`   integer (default: 1)
        Inset from the anchored corner. Positive is down for `"N*"`, up
        for `"S*"`.
    `col_offset`   integer (default: -1)
        Inset from the anchored corner. Positive is right for `"*W"`, left
        for `"*E"`.
    `border`       string or string list (default: `"rounded"`)
        |nvim_open_win()| border style.
    `winblend`     integer 0..100 (default: 0)

                                            *agentic-config-permission_icons*
`permission_icons` table
    Icon per permission option kind: `plan_implement`, `allow_once`,
    `allow_always`, `reject_once`, `__reject_all__`, `reject_always`.

------------------------------------------------------------------------------
4.6 SESSION RESTORE                           *agentic-config-session-restore*

                                             *agentic-config-session_restore*
`session_restore` table
    `storage_path`      string | nil
                        (default: `~/.cache/nvim/agentic/sessions/`)
    `picker`            `"quickfix"` | `"fzf-lua"` | `"select"`
                        (default: `"quickfix"`)
        Session picker backend. `"quickfix"` offers delete, undo and a
        scope toggle; `"fzf-lua"` adds a preview and falls back to
        quickfix when not installed; `"select"` delegates to
        |vim.ui.select()| and offers neither scope toggle nor delete.
    `confirm_delete`    boolean (default: true)
        Prompt before `/delete`.
    `cd_on_load`        boolean (default: true)
        Change nvim's working directory to the session's recorded cwd on
        load. Applies to the picker, `:Agentic {query}` and
        |agentic.load_acp_session()|.

------------------------------------------------------------------------------
4.7 HOOKS                                               *agentic-config-hooks*

                                                   *agentic-config-hooks-tbl*
`hooks` table
    Callback functions for lifecycle events:
      `on_prompt_submit`       Fires after submitting a prompt. Once per
                               dispatched block, so a submit that splits at a
                               command line fires it more than once.
      `on_response_complete`   Fires when response finishes. Once per
                               submitted prompt, so turns resent by
                               |agentic-config-auto_retry_on_transient_error|
                               report only the final outcome.
      `on_permission_request`  Fires on tool permission prompt.

    Each receives a data table with `session_id` and event-specific
    fields. See type annotations in `config_default.lua`.

------------------------------------------------------------------------------
4.8 SETTINGS                                         *agentic-config-settings*

                                                 *agentic-config-settings-tbl*
`settings` table
    `move_cursor_to_chat_on_submit`  boolean (default: false)
        Move focus to the chat window after submitting a prompt.
    `send_register`                  string | nil (default: nil)
        Register to copy the sent text into before a partial send deletes
        it from the input buffer. Nil writes no register.
    `write_submit`                   boolean (default: true)
        `:w` in the input buffer submits it, also during a usage limit, so
        `:wq` and `:x` submit and close the input window. The input is
        'modified' while it holds text, so |:qa| refuses to quit. When
        false the input is a plain buffer.

4.9 MISCELLANEOUS                                        *agentic-config-misc*

                               *agentic-config-auto_retry_on_transient_error*
`auto_retry_on_transient_error` boolean (default: true)
    When a turn ends in a transient server error (connection closed
    mid-response, API unreachable, overloaded), send "continue"
    immediately as a new turn, up to 3 times. The retried turns write
    nothing to the chat: no prompt heading, no error block, no bell or
    `[idle]` badge. Once the budget runs out the error is written as
    usual, followed by the number of attempts made. Tools already run in a
    retried turn may run again.

                                                      *agentic-config-winbar*
`winbar` boolean (default: true)
    Set 'winbar' on widget windows to the full header text.

                                                     *agentic-config-headers*
`headers` table
    Customise window headers per panel. Each entry can be a table with a
    `title` field or a function receiving header parts.

                                               *agentic-config-notifications*
`notifications` table
    `bell`    boolean (default: true)
        Ring the terminal bell when the agent needs attention. See
        |agentic-attention|.

                                                 *agentic-config-file_picker*
`file_picker` table
    `enabled`       boolean (default: true)
    `max_files`     integer (default: 20000)

                                                 *agentic-config-image_paste*
`image_paste` table
    `enabled`    boolean (default: true)
        Enable image drag-and-drop to add images to referenced files.

                                                      *agentic-config-follow*
`follow` table
    `enabled`           boolean (default: true)
        Master switch. When false, no programmatic scrolling.
    `pause_on_prose`    boolean (default: true)
        Pin the start of each prose run to the top of the viewport during
        streaming. See |agentic-follow|.
    `bottom_padding`    integer (default: 1)
        Rows kept below the last buffer line.

                                                 *agentic-config-status_icons*
`status_icons` table
    Tool call state icons: `pending`, `in_progress`, `completed`, `failed`,
    `cancelled`.

                                             *agentic-config-diagnostic_icons*
`diagnostic_icons` table
    Context panel diagnostic icons: `error`, `warn`, `info`, `hint`.

                                                       *agentic-config-debug*
`debug` boolean (default: false)
    See |agentic-debug|.

                                                         *agentic-config-log*
`log` boolean (default: false)
    See |agentic-debug|.

5. LUA API                                                       *agentic-api*

All functions are on `require("agentic")`. The functions that act on a
session act on the session of the current buffer, else on the session
last created or entered, else on a new session.

                                                             *agentic.setup()*
agentic.setup({opts})
    Merge {opts} into the configuration. Optional. See
    |agentic-configuration| for available options.

                                                              *agentic.open()*
agentic.open({opts})
    Show the session's chat: focus a window in the current tabpage that
    shows it, else show it in the current window. From an input or a
    widget panel, show it instead in the chat window of that buffer's
    session, else in a split above the current window. Optional `opts`
    table:
      `mods`                 |:command-modifiers| as in |nvim_cmd()|. With a
                             split or tab modifier the chat opens in a new
                             window, and its panels move there.
      `auto_add_to_context`  Add the current selection or file to the
                             context first (default: true).
      `query`                A `session_id` prefix or an exact title. Open
                             the cached session it matches instead, as
                             |:Agentic| does with {query}.

                                                       *agentic.send_prompt()*
agentic.send_prompt({text})
    Send {text} as a prompt to the active session. The prompt is held and
    sent later if the session cannot take it yet; a second call before the
    first is sent replaces it.

                                                     *agentic.add_selection()*
agentic.add_selection()
    Add the current visual selection to the context panel.

                                                          *agentic.add_file()*
agentic.add_file()
    Add the current file to the context panel.

                                  *agentic.add_selection_or_file_to_context()*
agentic.add_selection_or_file_to_context()
    Add visual selection if active, otherwise the current file.

                                      *agentic.add_current_line_diagnostics()*
agentic.add_current_line_diagnostics()
    Add diagnostics from the cursor line to context.

                                           *agentic.add_buffer_diagnostics()*
agentic.add_buffer_diagnostics()
    Add all buffer diagnostics to context.

The `add_*` functions and |agentic.send_prompt()| notify what they added
when the chat's window is not in the current tabpage.

                                                       *agentic.new_session()*
agentic.new_session({opts})
    Start another chat session and show it as |agentic.open()| does. The
    previous sessions stay alive. Takes the `opts` of |agentic.open()| and
    `provider`.

                                                  *agentic.load_acp_session()*
agentic.load_acp_session({session_id}, {cwd}, {model})
    Load a specific ACP session by UUID into a new session and show its
    chat. Optional {cwd} for the working directory and {model} for the
    model id saved with the session. On failure, the saved transcript is
    replayed as context on the next prompt. When the session is already
    open, shows its chat instead.

                                                   *agentic.resolve_session()*
agentic.resolve_session({query}, {callback})
    Resolve {query}, a `session_id` prefix or an exact title,
    case-insensitive, against the session cache. {callback} receives
    `session_id`, `cwd` and `model`, or nil when zero or several sessions
    match.

                                                 *agentic.send_operatorfunc()*
agentic.send_operatorfunc({type})
    'operatorfunc' callback for sending a motion/selection as a prompt.

6. KEYMAPS                                                   *agentic-keymaps*

Buffer-local keymaps set automatically in agentic buffers. All are
configurable via `keymaps` in |agentic-config-keymaps|.

------------------------------------------------------------------------------
6.1 WIDGET KEYMAPS                                    *agentic-keymaps-widget*

Applied to all buffers in the widget (chat, prompt, panels).

    Key              Mode    Description ~
    `<localLeader>m`   n/v     Switch agent mode
    `<C-c>`            n/i     Stop generation
    `<localLeader>c`   n       Put "Continue" in the input (canned prompt)
    `<localLeader>R`   n       Restore session
    `<localLeader>p`   n       Switch provider
    `<localLeader>M`   n       Switch model
    `<localLeader>!`   n       Restart session
    `<localLeader>f`   n       Toggle changed-files panel
    `<localLeader>a`   n       Toggle follow (|agentic-follow|)
    `<localLeader>G`   n       Scroll chat and transcripts in the tabpage to bottom, keep focus

Canned prompts live in `keymaps.prompts` (|agentic-config-keymaps-prompts|).

------------------------------------------------------------------------------
6.2 PROMPT KEYMAPS                                    *agentic-keymaps-prompt*

    Key              Mode    Description ~
    `<CR><CR>`         n       Send N lines (count1), delete them
    `<CR>{motion}`     n       Send the motion range, delete
    `<CR>`             x       Send the visual selection, delete
    `<S-CR><S-CR>`     n       Queue N lines (count1) for later dispatch
    `<S-CR>{motion}`   n       Queue the motion's line(s) for dispatch
    `<S-CR>`           x       Queue the selected line(s) for dispatch
    `<S-C-c>`          n       Drop every queued region (text stays as draft)
    `:w`               c       Submit (|agentic-config-settings-tbl|)

`<S-CR>` and `<S-C-c>` require a terminal with the kitty keyboard protocol.

`paste_image` (default off) pastes a clipboard image through img-clip.nvim.

What the queue bindings dispatch, and when, is in |agentic-queue|.

------------------------------------------------------------------------------
6.3 CHAT KEYMAPS                                        *agentic-keymaps-chat*

    Key    Mode    Description ~
    `[[`     n       Previous prompt or notice
    `]]`     n       Next prompt or notice

`[[` and `]]` also move between the rows of a subagent transcript.

|gf|, |CTRL-W_f| and |CTRL-W_gf| open file and buffer names in the chat and
the subagent transcripts. On `/skill` in the chat, the transcripts, the input
and the todos, they open that skill's SKILL.md. On a diff row where they find
no file, they open the edited file at that row's line: in the window, in a
split, or in a new tabpage. A count is ignored there.

Tool output over its line threshold (|agentic-config-tool-display|) is
folded; |zo|, |zc| and |za| toggle a fold as usual.

An insert key (`i`, `a`, `o`, `c`, `x`, ...) starts insert in an input: a
background subagent's transcript in its message input (|agentic-subagents|),
the chat, a panel or any other transcript in the session's. It uses the
input's window in the current tabpage, else opens the input panel below the
chat's window (|agentic-buffers|) when the current tabpage shows the chat,
else opens one below the current window. `p` and `P` in the chat paste there.

------------------------------------------------------------------------------
6.4 PERMISSION KEYMAPS                            *agentic-keymaps-permission*

Mapped in every widget buffer of a session while its permission float is
shown in the current tabpage. Set with `keymaps.permission`, keyed by
option kind. A permission key shadows a key with the same lhs while the
prompt is active. What each option does is in |agentic-permissions-prompt|.

    Key              Kind             Option ~
    `<localLeader>y`   `allow_once`       Allow once
    `<localLeader>Y`   `allow_always`     Allow always
    `<localLeader>n`   `reject_once`      Reject once
    `<localLeader>N`   `reject_always`    Reject always
    `<localLeader>x`   `__reject_all__`   Reject all
    `<localLeader>i`   `plan_implement`   Clear context & implement plan

An option whose kind has no key, or whose kind's key an earlier option
took, gets `<localLeader>` and its position, for example `<localLeader>3`.

While a subagent's prompt shows on the chat (|agentic-permissions-prompt|),
the `keymaps.permission_open` keys open its transcript. The prompt stays
pending and moves to the transcript's window. `false` disables a key.

    Key              Field    Opens the transcript in ~
    `<localLeader>e`   `edit`     The current window (*)
    `<localLeader>s`   `split`    A split
    `<localLeader>v`   `vsplit`   A vertical split
    `<localLeader>t`   `tab`      A new last tabpage

(*) From an input or a widget panel other than the chat: the chat's window.

The float's footer lists the enabled keys, with a shared prefix written once:
`\{e,s,v,t}`. Without a border, the list is the float's last line.

8. PERMISSIONS                                           *agentic-permissions*

------------------------------------------------------------------------------
8.1 THE PERMISSION PROMPT                         *agentic-permissions-prompt*

A tool call the agent is not cleared to make raises a prompt in a float
(|agentic-config-permission_float|) on the window showing that tool call's
buffer: the chat, or the subagent's transcript. While no window shows the
transcript, the float shows on the chat, titled with the transcript's name,
and the open keys (|agentic-keymaps-permission|) open the transcript. A float
outside the current tabpage counts as hidden (|agentic-attention|). The
options come from the provider; the plugin inserts "Reject all" ahead of the
provider's
"Reject always", or appends it when there is none. When the agent leaves
plan mode, the plugin adds "Clear context & implement plan" first. Keys:
|agentic-keymaps-permission|.

    Option          Effect ~
    Clear context & Accept the plan, then start a new session and send it
    implement plan  the plan file.
    Allow once      Approve this call.
    Allow always    Approve, and approve the same operation for the rest of
                    the session without prompting.
    Reject once     Reject this call.
    Reject all      Reject this call and cancel every call still queued for
                    the turn. No rule is stored.
    Reject always   Reject, and reject the same operation for the rest of
                    the session without prompting.

An always-decision applies to calls with the same file path, command, URL
or query.

Execute prompts highlight unapproved command parts:
|AgenticUnapprovedCommand|.

------------------------------------------------------------------------------
8.2 AUTO-APPROVAL                                   *agentic-permissions-auto*

A tool call runs without a prompt when any of these holds. The word after
each item is what the call's status footer shows (`✔ completed · grant`).

- Its kind is in `permissions.auto_approve_kinds`. The kind, such as `read`
- It is a shell command every leaf of which is allowed
  (|agentic-permissions-shell|), by a `read_only` rule (`read-only`), a
  `safe_write` rule (`safe-write`), a settings.json `Bash(...)` pattern
  (`glob-allow`) or a leaf remembered by "Allow always" (`session-allow`).
  A redirect or `rm` under a granted path adds `grant`.
- It matches a cached "Allow always" decision
  (|agentic-permissions-prompt|). `session-allow`
- It is a recoverable change under a granted path
  (|agentic-permissions-grant|). `grant`

Several words mean each was needed. `deny`, `glob-deny` and `session-reject`
name what rejected a call. A prompted call shows `prompt-allow` or
`prompt-reject`. A call with no word was decided by the provider, or was
cancelled while its prompt was open.

------------------------------------------------------------------------------
8.3 GRANTS                                         *agentic-permissions-grant*

`/grant` adds a path to the session's grants. Under a granted path, file
tool calls (edit, write, create, delete, move), shell redirects (`>`, `>>`)
and `rm` auto-approve when the change is recoverable. Grants last until the
session ends.

    `/grant .`        The session's working directory.
    `/grant root`     The git root of the working directory.
    `/grant {path}`   A path or glob. A relative path resolves against the
                      working directory; `~` and `$VAR` expand. The path
                      need not exist.
    `/grant off`      Remove every grant.
    `/grant`          Open a picker to add or remove grants.

A directory named `root` or `off` is granted as `./root` or `./off`.

A path covers everything below it. A glob covers the paths it matches. Below
the granted directory, a file or directory whose name starts with `.`
(`.git`, `.env`) is excluded unless the path names it: `/grant .github`, or
`/grant **/.github/**`. A symlink needs both the link and its target granted.

A change is recoverable when:
- the file does not exist,
- the file is tracked by git and has no uncommitted change, or
- an edit to a tracked file only adds lines, or changes no line with an
  uncommitted change other than lines the agent wrote earlier in the
  session that are unchanged since.
A delete needs a tracked file with no uncommitted change.

An untracked file under `/tmp` or `$TMPDIR` can always be written, created
or edited. An `rm` of one needs the file redirected to earlier in the same
command, and `permissions.tmp_cleanup` on.

A redirect or `rm` target must be an absolute path with no `..` segment.

`permissions.default_grant` is granted at session start. An entry naming an
unset variable is skipped.

------------------------------------------------------------------------------
8.4 SHELL COMMANDS                                 *agentic-permissions-shell*

Every Bash command is parsed with the `zsh` treesitter grammar
(|agentic-requirements-parsers|) and its leaf commands are matched one by
one, so `cd /path && git status` matches a `git` rule on its `git` leaf.

The walk rejects by default: a missing parser, a parse error, command or
process substitution (`$(...)`, backticks, `<(...)`), control flow (loops,
conditionals, subshells, functions), a file-writing redirect outside a grant
(|agentic-permissions-grant|; `/dev/null` and fd duplication such as `2>&1`
are not file-writing), a dynamic command name, or
a code-taking builtin (`eval`, `source`, `.`) all fall through to a prompt.

Each remaining leaf is stripped of a `stdbuf` wrapper and a system
binary-dir prefix, then checked against two layers:

- Structured rules: the bundled `permissions.json` plus
  `permissions.structured`. These match on tokenised flag identifiers, so
  option clustering (`sort -uo out`), GNU abbreviation (`sort --out=x`)
  and glued arguments (`sort -oFILE`) are matched.
- Claude's settings: the `Bash(...)` entries of the `allow`, `deny` and
  `ask` lists in `settings.json` in Claude's config directory
  (`CLAUDE_CONFIG_DIR` from the provider's `env` or the environment, else
  `~/.claude`) and in `.claude/settings.json`.

A leaf auto-approves when a layer allows it and no layer denies or asks.
`deny` rejects the command immediately, with no prompt and no execution;
`ask` withholds approval so the command prompts. Which allow rules count
follows `permissions.auto_approve_tier`, the highest rule kind that counts:
`"safe_write"` admits `safe_write` and `read_only` rules, `"read_only"`
admits `read_only` rules, nil admits none. A settings.json `allow` entry
counts unless `auto_approve_tier` is nil.

Structured rules are a cmd-keyed table. Each command maps to up to four
gate-kind arrays, `read_only`, `safe_write`, `ask` and `deny`, and each
gate constrains `options` (literal flag identifiers) and/or `positionals`
(literal or glob, matched in order). An identifier is a letter for a short
option (`o`, also inside a cluster `-uo`) or a name for a long option
(`output` for `--output`). `ask` and `deny` also match an abbreviation
(`--out`); `read_only` and `safe_write` match only the exact identifier.
An option of unknown arity may or may not take the next word as its
value, and a `read_only` or `safe_write` gate must match in every
combination of these readings.
A command's optional `arity` field lists, per scope, the literal option
tokens that take a value (`takers`) and that take none (`booleans`).
A token is a letter (`-x`, also inside a cluster) or a long name
(`--name`); other tokens are ignored with a warning. Scope `""` is before
the first positional, a literal first positional (`config`) is after it,
and `"*"` is every scope. A missing hint only adds prompts; a wrong hint
can auto-approve a write.
`permissions.structured` is deep-merged over the bundled defaults: a cmd key
replaces that command's bundled kind-arrays wholesale, `arity` merges per
scope and field, and `vim.NIL` disables the bundled entry. >lua
    require("agentic").setup({
        permissions = {
            structured = {
                -- Auto-approve `tee` when writing (safe_write kind).
                tee = { safe_write = { {} } },
                -- Remove the bundled `rm` entry (`nil` or `{}` keep it).
                rm = vim.NIL,
                -- Silence pacman's destructive-flag ask.
                pacman = { ask = {} },
                -- `-o` takes a value, `-n` takes none.
                foo = {
                    arity = { ["*"] = { takers = { "-o" }, booleans = { "-n" } } },
                },
            },
        },
    })
<

9. CHAT BEHAVIOUR                                               *agentic-chat*

------------------------------------------------------------------------------
9.1 SESSIONS AND BUFFERS                                     *agentic-buffers*

Each session has its own chat, panels and permission prompts. A session
lives as long as its chat buffer, which is listed.

    Command              Effect ~
    `:w` in the chat       Writes the history to the session file.
    `:bd` on the chat      Ends the session and wipes its buffers.
    `:e` / `:e!`           Re-renders the buffer from its session.
    `:bd` on a transcript  Unloads and unlists it; its agent's output reloads it.
    `:bw` on a transcript  Wipes it; its agent's output makes it again.

The chat is 'modified' while a running turn's history is not yet written. An
idle session writes its history as it changes, except a subagent's text,
which is written when one of its tool calls ends, at the next turn's end, or
on `:w`.

Each subagent transcript (|agentic-subagents|) is a listed buffer saved with
the session. It is 'modified' while the session's history is not yet
written, and `:w` on it writes the session file.

Notices, errors and the session-start line are not saved: `:e` and a
restore do not render them again.

A session with no messages and an empty input ends when no window shows its
chat: after |:q| on its chat window, or |:e| or |gf| there.

The chat shows in any window, like any buffer. Its panels attach to one
window showing it, the chat's window: the first window the chat enters
while it has none, or the window |agentic.open()| opens. In a tabpage
without the chat's window, a key that opens a panel (an insert key, `p`,
`<localLeader>f`) makes a window there that shows the chat, the current one
first, the chat's window. The panels stack
below it in `windows.stack` order (|agentic-config-windows-tbl|). The context
panels open while they list something. The input opens on the first insert
key (|agentic-keymaps-chat|). `<localLeader>f` toggles the file activity
panel.

When the chat's window closes or shows another buffer, its panels close.
|:q| in the chat's window closes its panels first; when vim refuses the
quit, they open again.

A panel window can show any buffer. While it shows a buffer that is not its
panel's, it is not a panel window. A 'winfixbuf' set in `win_opts` stops |gf|
and |:e| in that window.

------------------------------------------------------------------------------
9.2 FOLLOW                                                    *agentic-follow*

Each window showing the chat is in one of two modes:

- User control: new output does not scroll the window.
- Following: the window scrolls with new output. It shows the trailing edge
  of the buffer, or with `follow.pause_on_prose` the start of the current
  prose run, pinned to the top of the viewport until the next non-prose write
  to chat. A prose run taller than the window puts the window in user
  control when its pin ends.

Moving the view or the cursor up, with keys or mouse, puts the window in
user control. It follows again when the view moves down to show the last
line, when the cursor moves onto the last line (e.g. |G|, or a closed fold
that ends there), on `<localLeader>G`, or when a prompt is submitted. Prompts
sent from the queue do not. Entering the window, e.g. by a click, and
resizing it do not change its mode.

A chat or transcript opens following. If the last window that showed it was
in user control, it opens at the same position, in user control. A |CTRL-]|
jump that opens it lands on the tag's row, in user control.

While a permission prompt is active, a following window shows the prompting
tool call instead: centred once, then up to its heading at the top as output
grows. With the prompt on the chat in place of a transcript, that is the
subagent's block. When the prompt ends, following goes back to the trailing
edge.

------------------------------------------------------------------------------
9.3 ATTENTION                                              *agentic-attention*

When a turn ends, the terminal bell rings if the chat window is not the
current window (`notifications.bell`), and the chat header shows `[idle]`
if no chat window follows (|agentic-follow|). `[idle]` stays until the next
submit.

When a permission float is shown, the bell rings if the chat window is not
the current window.

When the float is not in the current tabpage, once per prompt, the bell
rings, the header of the tool call's buffer (the chat, or a transcript; the
chat while no window shows the transcript) shows `[?]`, and a notification
names the session and the tool call's buffer. `[?]` stays until the prompt is
answered.

Auto-approved requests do none of this.

------------------------------------------------------------------------------
9.4 MESSAGE QUEUE                                              *agentic-queue*

Submitted text splits at command lines: a line of the form `/word`, with or
without arguments, is a prompt of its own, and each run of other lines is one
prompt. They dispatch in buffer order, one per turn: `/compact` above
`Continue` compacts, then sends `Continue` when that finishes. Text with no
command line in it is one prompt. An argument belongs on its command's own
line; the line below it is the next prompt. A `/`-leading line indented by
one space is ordinary text.

The queue bindings (|agentic-keymaps-prompt|) tag the covered line(s) as a
queued region (`AgenticQueuedRegion`, |agentic-highlights|) instead of
sending now, whether or not a turn is running. Queueing is
line-granular: a charwise motion queues its whole line(s). A submit the
session cannot take yet is tagged the same way, as is every block of one that
has not dispatched.

The queue dispatches one block in buffer order at each turn that ends
normally, and one when a session becomes ready. A turn stopped with `<C-c>`,
or ended early by the agent, leaves the rest tagged; a refused turn leaves
them as draft. Editing a region (any change to it, or entering insert mode
with the cursor inside it) drops it back to ordinary draft.

When the agent refuses a prompt, the prompt goes back to the top of the input
it was sent from, and its context goes back in the context panels. The refused
message stays in the agent's conversation.

`/new`, `/clear` and `/delete` ask for confirmation when they dispatch from
the queue rather than as a submit's first block. Declining leaves every
queued block as draft. Once it has deleted the session, `/delete` also
drops the rest of the queue.

------------------------------------------------------------------------------
9.5 FILE ACTIVITY                                      *agentic-file-activity*

A toggled panel listing the files the agent has changed over the session,
one row per file however many times it was touched. Subagent (Task) edits
appear alongside the main agent's, unmarked.

Toggle with `<localLeader>f`. The chat header carries the number of changed
files.

    Row      Meaning ~
    `+ path`   File created
    `~ path`   File changed
    `- path`   File deleted

A `●` in the panel's sign column marks a row changed since the panel was last
open. The marks clear when the panel is closed, and survive a resume.

Rows are ordered by change class (changes above plain reads), then by
location (project files, elsewhere, then scratch), then alphabetically.
Inside the panel:

    Key   Description ~
    `<CR>`  Open the file at its first recorded change
    `Q`     Send every row to the |quickfix| list

Opening the panel drops rows whose change is no longer on disk: a created
file that no longer exists, and a tracked file that no longer differs from
HEAD, so committing the agent's work drops its rows. Rows for untracked
files that still exist, and every row outside a git repository, stay.
`windows.activity.hide_reverted = false` keeps them all.

The list survives a session restore and a provider switch. `/new`
and `/clear` start a new conversation, and empty it.

Only the file-editing tools are tracked. Files a shell command changes are
not listed.

------------------------------------------------------------------------------
9.6 SUBAGENTS                                              *agentic-subagents*

With claude-agent-acp, each subagent has its own transcript: a listed buffer
named `agentic://<id>/subagent/<agent id tail>-<name>` holding its prose,
thinking and tool calls under a `##` heading like its block's. A transcript
shows its subagent as working while it works. It also has a row for each end
of a run, titled `completed`, `cancelled`, `failed`, `ended`, `unknown` or
the provider's stop reason. The header shows how the last run ended. A
resumed subagent continues in the same transcript.

A message between agents, the launch prompt included, has a row in the chat
or transcript of each agent it joins: `From <name>` with the text in the
recipient's, `To <name>` with the recipient's buffer name in the sender's.
Each message is a tag named by its id, defined at both rows: |CTRL-]| on
either row jumps to the other, |CTRL-T| jumps back, and |:tag| or
|:tselect| with the id lists both.

Each subagent also has a block in the chat, which records its launch:

    Line             Content ~
    Heading          `<mode> <type> · <name>`
    Name             The transcript's buffer name
    Footer           `completed`

The mode is `Background` or `Blocking`, with a `?` until the SDK's record
of the spawn confirms it; the type shows once that record is read. |gf|,
|CTRL-W_f| or |CTRL-W_gf| on the name line opens the transcript.

A provider crash and a session switch end every running subagent. A cancel
ends the subagents that the provider then reports ended.

A permission prompt from a subagent whose transcript has no window shows on
the chat (|agentic-permissions-prompt|).

An insert key in a background subagent's transcript opens its message input.
`:w` there sends the text to the subagent through the main agent, as your
prompt in the chat; `@path` stays text. `<C-c>` in either buffer asks the
main agent to stop the subagent. A blocking subagent has no message input: in
its transcript, insert keys go to the session's input and `<C-c>` stops the
turn. A restored background subagent gets its input when it runs again.

Transcripts are saved with the session (|agentic-buffers|) and come back on
load and restore.

13. DEBUG AND LOGGING                                          *agentic-debug*

>lua
